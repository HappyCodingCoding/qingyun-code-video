# 制作规则

## 页面骨架

```html
<script>
window.ready = false;                       // 字体、图片、模型加载完再置为 true
window.render = function (t) {              // t：时间轴上的秒数，成片从视频开头算起，预览从镜头开头算起
  // 1. 由 t 算出每个元素的状态（位置、缩放、透明度、颜色……）
  // 2. 画出来 / 写进 style
};
document.fonts.ready.then(() => { window.render(0); window.ready = true; });
</script>
```

这是网页的写法。框架的对应做法见 code-stack.md 的「两种出片方式」：Remotion 用当前帧号，HyperFrames 用暂停的时间轴，Manim 按顺序搭场景。

## 字体

- 中文字体按系统有差别：macOS 有 PingFang SC，Windows 有 Microsoft YaHei，Linux 常见 Noto Sans CJK。CSS 里写成一串兜底：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", sans-serif`。
- 要在不同机器上渲染出一样的效果，就把字体文件放进项目目录用 `@font-face` 本地加载（比如开源的思源黑体，即 Noto Sans SC），不要依赖网络字体。
- Canvas 和 WebGL 里用到的字体，要先用 `document.fonts.load('<字号> "<字体名>"')` 主动加载，等它完成再置 `window.ready = true`：画布上写字不会触发字体下载，只等 `document.fonts.ready` 时，前几帧会用默认字体。
- 像素风里的中文：先在小画布上用正常字体画，再按透明度取阈值（比如 alpha > 0.5 算实心）变成硬边像素，字号至少 16px，否则笔画会糊成一团；或者直接用 12px 的中文像素字体（比如 Fusion Pixel、Zpix）。小画布要按字数加大，128×96 一行只放得下五六个 16px 的字。

## 每一帧只由它在视频时间轴上的时间点算出

为什么每一帧只能由它的时间点算出：渲染脚本会按任意顺序、任意次数调用 render(t)（单帧预览、只重渲某一段、运动模糊的子帧）。只要有一点状态藏在上一帧里（累加的位置、计时器、未设种子的随机数），重渲出来的画面就会跟上一次不一样。

- 随机：不用 `Math.random()`，用由整数种子算出来的伪随机，同一个种子永远得到同一个数：
  ```js
  function rnd(seed) {                               // seed 为整数，返回 [0, 1) 之间的数
    let x = Math.imul(seed ^ 0x9e3779b9, 0x85ebca6b);
    x ^= x >>> 13; x = Math.imul(x, 0xc2b2ae35); x ^= x >>> 16;
    return (x >>> 0) / 4294967296;
  }
  ```
- 需要累积的模拟（粒子物理、水面）：用固定步长从 0 推算到 t，或者改成解析公式；按顺序渲染时可以缓存，但单帧预览必须也能算对。
- 自带时钟的动画都不用：CSS 的 transition 和 animation、SVG 的 `<animate>`、GIF 动图都按真实时间播放，渲染时会错帧。所有样式在 render(t) 里直接写；库的动画循环怎么关见 code-stack.md 的「网页（默认）」。
- 手绘质感：笔触的随机种子用 `floor(t * 12)`，笔触每秒只变 12 次，看起来像手绘动画；镜头运动仍然每帧平滑。

## 常用动画工具

- 缓动：`smoothstep` 或 cubic in-out 就够，匀速运动看起来很机械。
- 弹簧（闭式解，不依赖上一帧）：
  ```js
  function spring(x, w = 16, z = 0.72) {            // x = 目标改变后经过的秒数；返回 0→1
    if (x <= 0) return 0;
    if (z >= 1) return 1 - Math.exp(-w * x) * (1 + w * x);   // 临界阻尼，不回弹
    const wd = w * Math.sqrt(1 - z * z);
    return 1 - Math.exp(-z * w * x) * (Math.cos(wd * x) + (z * w / wd) * Math.sin(wd * x));
  }
  // 值多次改变目标：v(t) = v0 + Σ (v_i − v_{i−1}) · spring(t − t_i)
  ```
  按用途分四档，同一支片子里同类元素用同一档：

  | 用途 | 手感 | 参考参数 |
  |---|---|---|
  | 按钮、开关、指示条的前沿 | 快、利落 | w 22–26，z 0.75–0.85 |
  | 卡片、容器、镜头 | 默认 | w 14–16，z 0.7–0.75 |
  | 大字、3D 物体、Logo 定版 | 沉、几乎不回弹 | w 9–11，z 0.85–1 |
  | 吉祥物、贴纸 | 活泼、明显回弹 | w 16–20，z 0.4–0.5 |

  一个值会多次改变目标（光标位置、容器宽度）时，不要重启弹簧，用上面的叠加写法，这样动作是连续的，而且第 812 帧也能单独算出来。
- 节拍：BPM → 每拍秒数 `60 / BPM`；关键动作放在拍点上，重拍（每小节第一拍）放最大的变化。
- 运动模糊：只在快速运动多的片子里用，渲染时间按子帧数成倍增加；各技术组合的做法见 code-stack.md。

## 画面

- 素材：图形、图标、纹理都用代码画出来，不用外部的图片和视频；仅使用用户提供的素材。
- 统一：整片只用一套风格（画风、配色、字体、版式、动效语言），同一个角色或元素在每个镜头里的样子都一致。若按段落切换风格是方案本身的设计（比如历史片每个年代换一种画风），在 production-spec.md 的 `<direction>` 里逐段写明各段的风格，配乐贯穿全片。
- 镜头：写清楚推、拉、跟随，主体至少占画面三分之一；若没写明，默认会使用固定机位，画面容易空。
- 文字：每个镜头只讲一件事，一屏最多一句，字要大，至少停留 2.5 秒；在变形容器里切换的文字要有自己的进场和出场时间，否则新旧文字会叠在一起。
- 转场：从画面内容里长出来（比如上一个镜头的元素变形成下一个镜头的主体，或镜头推进穿过某个元素），不用默认的淡入淡出。
- 被缩放的元素、会渲染文字的元素，不要加 `will-change`，文字会糊。
- Canvas：画布的 `width`、`height` 属性设成输出分辨率（render.py 的设备像素比固定为 1），不要只用 CSS 把小画布拉大，否则会糊。像素风例外：小画布按整数倍放大，关闭平滑（`imageSmoothingEnabled = false`，用 CSS 放大时加 `image-rendering: pixelated`），坐标取整。
- WebGL：`getContext('webgl2', { preserveDrawingBuffer: true })`，每帧画完调用 `gl.finish()`；先渲一帧确认着色器真的生效了，再渲整片。
- 循环视频：`render(时长)` 和 `render(0)` 的画面完全一样，包括光标位置和速度。render.py 不渲染 t = 时长这一帧，所以接缝处不会重复；若让最后一帧和第一帧一样，接缝处会多出一帧停顿。
- 安全区：文字和关键内容离画面边缘至少留 5%；竖屏发短视频平台时，底部约 20% 和右侧约 15% 会被标题、按钮挡住，不放重要内容。
- 字幕：按 `audio/voice.json` 的逐句时间，在 render(t) 里画出当前这一句；放在安全区内，一行放不下时按意思断成两行。
- 多画幅（9:16 / 1:1 / 16:9）：场景按版式函数排，尺寸和位置按窗口宽高（`innerWidth`、`innerHeight`，或 CSS 的 `vw`、`vh`）算，不要写死像素，这样换画幅、出半分辨率低清版都不会错位；每个画幅单独调整文字和界面的位置，再从同一条时间轴各渲一版。不要把 16:9 的成片直接裁成竖屏。
- 默认风格要主动避开：深色背景 + 居中大字 + 所有元素淡入淡出，这是没有任何限制时最容易出来的样子。风格本身需要深色时（CRT、夜景、霓虹）照用，但排版和运动要有自己的设计。在 production-spec.md 的「禁止」一项里写明要避开什么。

## 声音

- 音效：网页在画面代码里登记音效，让音效和动作用同一个时间变量，改动作时间时音效跟着走：
  ```js
  const SFX = [];
  const sfx = (t, sound, gain = 0.6) => (SFX.push({ t, sound, gain }), t);   // 返回 t，可直接当动作的起点
  window.sfxEvents = SFX;
  // 例：pop(t, sfx(T.cut, 'whoosh'), ...) —— 动作在 T.cut 开始，同一刻放 whoosh
  ```
  t 用视频时间轴上的秒数（镜头代码用镜头自己的时间时，加上镜头起点）。登记要在载入时完成：在置 `window.ready = true` 之前把每个镜头的代码按镜头结尾的时间各跑一遍（这时所有元素都已出场，条件分支里的 sfx() 也会执行）；只在 render(t) 里登记会漏掉还没画到的动作。render.py `--sfx-events` 导出时，同一时间点的同一种音效只保留一个。框架手写 `audio/sfx-timeline.json`，时间点从画面代码的关键帧时间抄。
- 用户给了音乐：按 SKILL.md 第 1 步测出的 `source/beats.json`，状态变化放在 beats 上，大的变化放在 downbeats 上，音效放在 hits 上。
- 配乐：按项目用 numpy 写成 `audio/music.wav`，BPM 和时长按 production-spec.md；鼓（下扫频正弦 + 快衰减）、贝斯、和弦铺底、旋律分轨合成再混；纯正弦很单薄，和弦和旋律叠上泛音、加一点失谐和混响。
- 配音：用 `python3 scripts/audio_tools.py tts` 合成，拿到逐句、逐词时间戳（`audio/voice.json`，词在每句的 `words` 里），再让画面去对旁白：镜头和段落对齐句子，句中的动作对齐词，不要按字数估算词的时间。它按段落（空行分隔）逐段合成，段与段之间插入停顿；一个段落放一个镜头或一个小节，不要一句一段，否则句间语调不连贯。
- 混音：`python3 scripts/audio_tools.py mix` 把配乐、音效和配音混在一起，配音出现时自动压低配乐（压得不够或太多时调 `--duck-ratio`，整体音乐偏响时调 `--music-gain`）；最后运行 `python3 scripts/audio_tools.py normalize audio/mix-raw.wav audio/mix.wav`，它会把响度调到 -14 LUFS（误差 0.5 LU 以内），并把真峰值压到 -1 dBTP 以下。
- 检查：`python3 scripts/audio_tools.py check audio/mix.wav --out qa/audio` 出响度数值、波形图和频谱图。模型听不到声音，只能看图：看有没有削顶、有没有意外的静音段、低频有没有一直轰着。

## 自检打分

打分对象是 SKILL.md 第 7 步渲好的低清版整片 `out/draft.mp4`（长片按章打）。先出抽帧图和手机尺寸抽帧图，用挑毛病的眼光看，别当自己是作者。

每项从 10 分起扣，最低 1 分，每扣一次都写下时间点和原因：
- 小问题扣 1 分：只出现在一处，不仔细看注意不到（比如某个字离安全区边缘太近）。
- 明显问题扣 3 分：观众一眼能看出，或在多个镜头里重复（比如新旧文字叠在一起、某个镜头 3 秒什么都不动）。

| 项 | 看什么 |
|---|---|
| 开场 | 第 0 秒的画面就有内容（不从黑屏或空画面淡入）；前 3 秒内有一句大字讲明视频讲什么，并且它是个钩子（大胆或有意思的说法、结论、反常识的数字），只看前 3 秒就知道这支视频讲什么；用 `python3 scripts/analyze_video.py out/draft.mp4 --out qa/opening --frames 0 1.5 3` 导出整帧进行检查 |
| 手机可读 | 缩到手机全屏播放时的宽度，字还看不看得清：16:9 按横屏播放缩到 640 像素宽，9:16、3:4、4:5、1:1 按竖屏播放缩到 360 像素宽；字号拿不准时，用正式分辨率的静帧对照 |
| 动作 | 有没有匀速滑动、有没有什么都不动的空拍 |
| 变化 | 每 2–4 秒有没有新东西出现 |
| 构图 | 主体够不够大，画面有没有空一大块或挤成一团 |
| 镜头交接 | 运行 `python3 scripts/analyze_video.py out/draft.mp4 --out qa/cuts --frames <各镜头的转场结束时间 + 0.1 秒> <各镜头起点 + 1.5 秒>`（转场结束时间的算法见「验收清单」的「没有残留元素」）：前一组整帧里没有上一个镜头的残留，后一组整帧里主体已经出现，不是只剩标题或标签。抽帧图每隔几秒才取一帧，这两类问题要靠这组整帧发现，在低清版上改完，正式版就不用再拼接修补 |
| 贴合原材料 | 配色、字体、事实和 production-spec.md 一致 |
| 声画同步 | 对照 `audio/sfx-timeline.json`、节拍或旁白时间轴和画面代码，音效和重拍的时间点是不是落在对应动作上（模型听不到声音，只能对时间） |

重点找这些常见问题：切换时新旧文字叠在一起、居中大字加渐变背景的默认画面、角落里多余的标签和边框、缩放后变糊的字、循环接缝处的卡顿。

快速动作附近的问题在抽帧图里容易漏掉，有快速动作的片段，要把那一段连续 12 帧拼成一条来看：
`ffmpeg -ss <秒数> -i out/draft.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 qa/strip.png`

循环视频先把成片接成两遍，再从接缝前 6 帧起拼一条，前 6 帧是结尾、后 6 帧是开头：
`ffmpeg -stream_loop 1 -i out/draft.mp4 -c copy qa/loop_check.mp4`
`ffmpeg -ss <时长 − 6 ÷ 帧率> -i qa/loop_check.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 qa/loop_strip.png`

**怎么用分数**

1. 低于 8 分的项必须修：先修明显问题，再修小问题，从分数最低的项修起。8 分及以上的项，剩下的小问题顺手能修就修。
2. 每处修改用正式分辨率的静帧或片段检查，不重渲整片；这一轮全部修好后重渲低清版，按同样的规则重新打分。
3. 每项都到 8 分及以上，进入「验收清单」。做满 3 轮仍有低于 8 分的项时，停止修改这些项，照样进入「验收清单」，把剩下的问题和时间点留到 SKILL.md 第 8 步的「无法解决的问题」里交代给用户。

每一轮在 `qa/review_log.md` 记一段：轮次、每项的分数、每次扣分的时间点和原因、这一轮改了什么。

## 验收清单

自检打分通过后逐项核对。每项都按「怎么确认」去查，不凭印象判断：

| 项 | 怎么确认 |
|---|---|
| 规格一致 | `qa/final-info.txt` 里的时长（误差不超过 1 帧）、像素尺寸和帧率与 production-spec.md 的「规格」一致，audio 为 yes |
| 没有空白帧 | 抽帧图和第 0 秒的整帧里，没有只剩背景、内容没画出来的帧 |
| 没有残留元素 | 运行 `python3 scripts/analyze_video.py out/final.mp4 --out qa/cuts --frames <各镜头的转场结束时间 + 0.1 秒>`，转场结束时间 = 镜头起点（取 production-spec.md 的 `<structure>`）+ 上一个镜头「转场」写的用时；导出的整帧里没有上一个镜头留下的元素。转场进行中上一个镜头的元素正在离开，不算残留 |
| 文字在安全区内 | 抽帧图和手机尺寸抽帧图里，所有文字都在「画面」一节规定的安全区内，没有溢出、没有被遮挡 |
| 字幕 | 不显示字幕时跳过；显示时，抽帧图里每一帧的字幕和那一刻的旁白一致，而且在安全区内 |
| 样子一致 | 同一个角色或元素在每个镜头里样子一致 |
| 没有禁止项 | 画面里没有出现 production-spec.md「禁止」里列出的做法 |
| 事实准确 | 逐条对照 `source/notes.md` 记下的事实，检查画面文字和旁白；无法确认的列出来，第 8 步交给用户核对 |
| 配音完整 | 没有配音时跳过；有配音时，`audio/voice.json` 最后一句的结束时间早于视频时长 |
| 响度 | 运行 `python3 scripts/audio_tools.py check out/final.mp4 --out qa/final-audio`，查交付的成片本身：响度在 -14 ± 1 LUFS 以内，真峰值低于 -1 dBTP |
